# 八卦モデルの設計

2026-09-28

## 目的

八卦を使う占いを、これから複数作る。予定しているのは易占（六十四卦）と九星気学。
その土台になる八卦のモデルだけを先に作る。画面と API は作らない。

## 方針

- 八卦は3ビットの数で表せる。ただし、関数の引数と戻り値は漢字（`'震'` など）にする
- 3ビットの値は、リストの index として持つ
- 爻（線）の操作は、線の本数を引数に取る関数として独立させる。六十四卦（6ビット）でも同じ関数を使うため

### 漢字で受け渡す理由

- 九星気学で使う属性（方位・九星の数・五行）は、ビットから計算できない。表で持つことになり、`Record<八卦, …>` にすれば抜けを型で検出できる
- 数の種類が多い。すべて `number` にすると、取り違えを型で防げない

| 数 | 範囲 |
| --- | --- |
| 3ビットの値 | 0〜7 |
| 先天数 | 1〜8 |
| 九星の数 | 1〜9（5 は卦なし） |
| 6ビットの値（伏羲の順） | 0〜63 |
| 文王の順 | 1〜64 |

- 既存の `十干` / `十二支` と同じ形になる
- テストの失敗やログが読める（`expected '震' to be '艮'`）

## ビットの決まり

| 卦 | 読み | 象 | 記号 | 3ビット | 先天数 |
| --- | --- | --- | --- | --- | --- |
| 乾 | けん | 天 | ☰ | `000` | 1 |
| 兌 | だ | 沢 | ☱ | `001` | 2 |
| 離 | り | 火 | ☲ | `010` | 3 |
| 震 | しん | 雷 | ☳ | `011` | 4 |
| 巽 | そん | 風 | ☴ | `100` | 5 |
| 坎 | かん | 水 | ☵ | `101` | 6 |
| 艮 | ごん | 山 | ☶ | `110` | 7 |
| 坤 | こん | 地 | ☷ | `111` | 8 |

- **陽 = 0、陰 = 1**
- **左の桁（上位ビット）が初爻（一番下の線）**。震 ☳ = `011` は、下から陽・陰・陰
- 並びは先天八卦（伏羲）の順。3ビットの値 + 1 が先天数になる
- Unicode の ☰ (U+2630) 〜 ☷ (U+2637) も同じ順。記号は計算で求めず、`記号list` として持つ（象と同じ形）。並びが Unicode と一致することは、テストで確かめる

下から n 番目（1始まり）の爻のビット位置は、線が N 本のとき `N − n` になる（最下位のビットを 0 とする）。
初爻は、3本なら位置 2、6本なら位置 5。本数によって変わるので、この計算は `Kou.ts` の中だけで行う。

一般には陽 = 1 とすることが多い（ライプニッツの対応）。
この設計では、先天数と Unicode の並びに一致することを優先して、陽 = 0 にする。

天文計算（`src/astronomy`）には依存しない。クライアントだけで動く。

`Hakke.ts` は `Kou.ts` に依存する。逆向きの依存は作らない。

`change爻` は `Kou.ts`（ビット列用）と `Hakke.ts`（卦用）の両方にある。
`index.ts` では、`Kou.ts` の関数を名前空間にまとめて出す（`Kou.change爻(bits, 6, 1)`）。

```ts
export * from './Hakke'
export * as Kou from './Kou'
export type { 陰陽, 爻数 } from './Kou'
```

## Kou.ts

ビット列（`number`）と線の本数を受け取る。八卦のことは知らない。

```ts
export type 陰陽 = '陽' | '陰'
export type 爻数 = 3 | 6
```

| 関数 | 内容 | 例（3本） |
| --- | --- | --- |
| `get爻list(bits, 爻数)` | 陰陽の配列にする。初爻 → 上爻の順 | `0b011` → `['陽', '陰', '陰']` |
| `from爻list(爻list)` | 陰陽の配列をビット列にする。本数は配列の長さ | `['陽', '陰', '陰']` → `0b011` |
| `invert爻(bits, 爻数)` | 陰陽をすべて反転する（錯） | `0b011` → `0b100` |
| `reverse爻(bits, 爻数)` | 上下を逆にする（綜） | `0b011` → `0b110` |
| `change爻(bits, 爻数, 位置)` | 指定した爻を反転する（変爻）。位置は 1 始まりで、1 が初爻 | `0b011`, 位置 1 → `0b111` |

### エラー

次の場合は `RangeError` を投げる。

- `bits` が整数でない、または `0` 〜 `2 ** 爻数 − 1` の範囲にない
- `位置` が整数でない、または `1` 〜 `爻数` の範囲にない
- `爻数` が 3 でも 6 でもない（`from爻list` では、配列の長さ）
- `from爻list` に渡した配列に、`'陽'` でも `'陰'` でもない要素がある

型の上では起きない値も検査する。JSON や URL クエリから来た値が、そのまま渡されることがあるため。

## Hakke.ts

```ts
// 並び順は先天八卦の順。indexがそのまま3ビットの値になる
export const 八卦list = ['乾', '兌', '離', '震', '巽', '坎', '艮', '坤'] as const
export type 八卦 = (typeof 八卦list)[number]

export const 象list = ['天', '沢', '火', '雷', '風', '水', '山', '地'] as const
export type 象 = (typeof 象list)[number]

export const 記号list = ['☰', '☱', '☲', '☳', '☴', '☵', '☶', '☷'] as const
export type 記号 = (typeof 記号list)[number]

export const 方位list = ['北', '北東', '東', '南東', '南', '南西', '西', '北西'] as const
export type 方位 = (typeof 方位list)[number]

export type 九星数 = 1 | 2 | 3 | 4 | 6 | 7 | 8 | 9
```

卦を受け取る関数は、八卦でない文字列（`'天'`、`'乾 '` など）を渡すと `RangeError` を投げる。

### 基本

| 関数 | 戻り値 | 例 |
| --- | --- | --- |
| `get読み(卦)` | 読み | `'震'` → `'しん'` |
| `get象(卦)` | 象 | `'震'` → `'雷'` |
| `get記号(卦)` | Unicode の記号 | `'震'` → `'☳'` |

### 3ビット

| 関数 | 戻り値 | 例 |
| --- | --- | --- |
| `toBits(卦)` | 3ビットの値 | `'震'` → `0b011` |
| `fromBits(bits)` | 卦。範囲外は `RangeError` | `0b011` → `'震'` |
| `get爻(卦)` | 陰陽の配列。初爻 → 上爻の順 | `'震'` → `['陽', '陰', '陰']` |
| `get先天数(卦)` | 1〜8 | `'震'` → `4` |

### 卦の変換

| 関数 | 内容 | 対応 |
| --- | --- | --- |
| `get錯卦(卦)` | 陰陽をすべて反転 | 乾↔坤、兌↔艮、離↔坎、震↔巽 |
| `get綜卦(卦)` | 上下を逆に | 兌↔巽、震↔艮。乾・離・坎・坤は自分自身 |
| `change爻(卦, 位置)` | 指定した爻を反転 | `'震'`, 位置 1 → `'坤'` |

`change爻` は `Kou.ts` にも同じ名前の関数がある。`Hakke.ts` の中では別名（`changeBits`）で import する。

### 後天八卦

| 卦 | 方位 | 九星の数 | 五行 |
| --- | --- | --- | --- |
| 坎 | 北 | 1 | 水 |
| 坤 | 南西 | 2 | 土 |
| 震 | 東 | 3 | 木 |
| 巽 | 南東 | 4 | 木 |
| 乾 | 北西 | 6 | 金 |
| 兌 | 西 | 7 | 金 |
| 艮 | 北東 | 8 | 土 |
| 離 | 南 | 9 | 火 |

| 関数 | 戻り値 |
| --- | --- |
| `get方位(卦)` | `方位` |
| `get九星数(卦)` | 1〜9（5 を除く） |
| `get五行(卦)` | `五行` |
| `from九星数(n)` | 卦。5（中宮）は卦が無いので `undefined`。1〜9 の整数でなければ `RangeError` |

向かい合う方位の卦は、九星の数を足すと 10 になる（坎1↔離9、坤2↔艮8、震3↔兌7、巽4↔乾6）。
これは錯卦とは一致しない（坤 `111` ↔ 艮 `110`）。

### 四維（しい）

後天八卦で、四隅の方位にある4つの卦。方位の名前としての読みを持つ。
読みは、その方位を挟む十二支から来ている。

| 卦 | 読み | 方位 | 十二支 |
| --- | --- | --- | --- |
| 乾 | いぬい | 北西 | 戌（いぬ）・亥（い） |
| 艮 | うしとら | 北東 | 丑（うし）・寅（とら） |
| 巽 | たつみ | 南東 | 辰（たつ）・巳（み） |
| 坤 | ひつじさる | 南西 | 未（ひつじ）・申（さる） |

```ts
export const 四維list = ['乾', '艮', '巽', '坤'] as const
export type 四維 = (typeof 四維list)[number]
export type 四維読み = 'いぬい' | 'うしとら' | 'たつみ' | 'ひつじさる'
```

| 関数 | 戻り値 |
| --- | --- |
| `is四維(卦)` | 四維の卦なら `true` |
| `get四維読み(卦)` | 四維の卦なら読み。それ以外（坎・震・離・兌）は `undefined` |

`get読み` が返す音読み（けん・ごん・そん・こん）とは別に持つ。

### 五行の型

`src/suimei/models/Kanshi.ts` にある `五行list` と型 `五行` は、今は export されていない。
これを export して、`Hakke.ts` から型だけを import する。

```ts
import type { 五行 } from '../../suimei/models/Kanshi'
```

共通の場所への移動は、九星のモデルを作るときに検討する。

## テスト

`swisseph` を使わないので、ローカルでも実行できる。日時を扱わないので、タイムゾーンにも依存しない。

### Kou.test.ts

- 3本と6本の両方で、各関数の結果を確かめる
- `from爻list(get爻list(bits, n))` が元の値に戻る
- `invert爻` と `reverse爻` は、2回行うと元の値に戻る
- 範囲外の値で `RangeError` が投げられる

### Hakke.test.ts

- 8つの卦すべてについて、上の表の値（読み・象・記号・3ビット・先天数・方位・九星の数・五行）を確かめる
- 錯卦と綜卦の対応を、8つすべてについて確かめる
- `fromBits(toBits(卦))` が元の卦に戻る
- `from九星数(get九星数(卦))` が元の卦に戻る。`from九星数(5)` は `undefined`
- 向かい合う方位の卦は、九星の数の和が 10 になる（方位と九星の数の表を、互いに照合する）
- 記号のコードポイントは、U+2630 + 3ビットの値になる
- 四維の読みを持つのは、方位が四隅（北西・北東・南東・南西）の卦だけ
